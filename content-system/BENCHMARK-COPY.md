# 教学文案基准调研（BENCHMARK-COPY）

> 2026-09-27。问题：同类网站/教育机构怎么写零基础教学文案？对照对象：v5 原站声音手册。
> 方法：抓取 6 家代表性产品的真实原文（非转述），拆结构、语气、密度，得出对铺量的操作结论。
> 附件性质：调研参考，不改 validate.mjs 门禁。

## 一、总览：三种文体

| 文体 | 代表 | 载体 | 单位长度 | 类比/人格化 | 适配我们的场景？ |
|---|---|---|---|---|---|
| 词典体 | MDN、Codecademy、菜鸟教程、**原站** | 词条/参考页 | 1–3 句定义 + 长正文 | 几乎无 | ✅ 与原站同路，是我们该学的 |
| 教程体 | 廖雪峰、freeCodeCamp | 长文章 | 一篇 10 分钟 | 大量类比 + 口语 | ❌ 文体不同：读者已投入整段时间 |
| 问答图解体 | 小林 coding | 面试向长文 | 问答对 + 图 | 人格化 + 生活类比 | ⚠️ 手法可偷，文体不搬 |

## 二、逐家原文与拆解

### 1. MDN（中文·词典体标杆）

定位：开发者官方参考。受众：有耐心的入门者。

> 「HTTP 是一种用作获取诸如 HTML 文档这类资源的协议。它是 Web 上进行任何数据交换的基础，同时，也是一种客户端—服务器协议，也就是说，请求是由接受方——通常是 Web 浏览器——发起的。」

结构：概念 → 角色（客户端/服务器/代理）→ 性质（简约/可扩展/无状态）→ 能力 → 流程 → 报文格式 → API。
语气：第三人称客观陈述，几乎不用「你」；长句带破折号插入；限定词多（「本质上」「大体上看」）。

**借鉴**：定义句 = 「X 是干什么用的东西」一锤定音；术语用链接外置（对应我们的 related 查重拆卡）。
**不抄**：长句、破折号插入、限定词堆叠——对 3 秒扫读的卡片是灾难。

### 2. Codecademy 词典页（英文·产品化词典体）

> 「Hypertext Transfer Protocol (HTTP) is used for fetching HTML documents and other web-based resources. It follows a model where a client (most commonly a browser) requests content stored on a server.」

结构：两句定义 → 相关课程链接 → HTTPS/请求/响应（状态码用表格）→ 缓存与代理。
语气：中性陈述句 + 表格承载枚举。长度：正文 500–700 词，大头是状态码表。

**借鉴**：**枚举交给表格**——我们的 quiz 字段和将来的测验页就是承接枚举的容器，正文保持短。
**不抄**：结尾的课程推销位。

### 3. 菜鸟教程 / W3School（中文·教材体）

> 「HTTP（超文本传输协议，HyperText Transfer Protocol）是一种用于分布式、协作式、超媒体信息系统的应用层协议。」

结构：定义 → 请求-响应原理 → 方法 → 状态码 → 版本 → 安全，纯概念递进，无场景无类比。
语气：百科腔，工整编号列表。受众：有计算机基础的初学者。

**反面教材（v4 踩过的坑）**：开篇「分布式、协作式、超媒体信息系统」三个术语前置不解释——正是 v4「不从共识出发」的错误，也是它对完全零基础不友好的原因。**这验证了 v5 的共识出发原则。**

### 4. 小林 coding《图解网络》（中文·问答图解体，流量最大的中文网络教材）

> 「HTTP 是一个在计算机世界里专门在『两点』之间『传输』文字、图片、音频、视频等『超文本』数据的『约定和规范』。」

拆字手法：把「协议」拆成「协 = 两个以上参与者 + 议 = 行为约定」、「超文本 = 超越普通文本的文本，是文字、图片、视频的混合体，最关键有超链接」。
辨析反例：抛出常见说法「HTTP 是用于从互联网服务器传输超文本到本地浏览器的协议」，判定**不正确**——因为也可以服务器对服务器，「两点之间」才准确。
结构：小标题即问题 → 短答 → 追问 → 反例辨析 → 小结；30 张手绘线图 + DevTools 真截图。
语气：人格化（「小林我」）、自嘲梗（「那你号没了」）。

**借鉴（三个可直接进武器库的手法）**：
1. **拆字枚举**：把术语的字面构成当枚举素材——「状态码 = 状态 + 码（给结果编号）」。对中文复合术语极其高效，是实例枚举的姊妹手法；
2. **辨析反例**：给一句「看起来对但不对」的说法让读者判——这就是我们 quiz 字段的题型来源之一；
3. **图承载机制**：文字只留结论，流程交给图（对应原站「深度靠更多卡片/图」的架构）。
**不抄**：人格化自称和玩梗——在长文里是亲密感，进卡片就是教练腔（v4 之死）。

### 5. 廖雪峰《Git 教程》（中文·教程体代表作）

> 「史上最浅显易懂的Git教程！」「不是难得令人发指，就是简单得一笔带过。」

结构：动机 → 是什么 → 安装 → 时光机（回退/撤销）→ 远程 → 分支。明确边界声明：「本教程只会让你成为 Git 用户，不会让你成为 Git 专家」。
语气：高度口语、自嘲、反问引导。

**借鉴**：**边界声明**值得学——我们的 explain 边界句就是它的卡片版；「时光机」这类章节命名比「版本控制基础」更勾人。
**不抄**：口语与情绪标记（「！！！」）——文体不匹配。

### 6. freeCodeCamp（英文·博客教程体）

> 「HTTP (Hypertext Transfer Protocol) is a protocol used for exchanging information over the internet.」

结构：为什么重要 → 前置知识声明 → 请求-响应循环 → 用 Chrome/Postman 现场发请求 → 方法/头/状态码逐个演示 → 书单。
语气：conversational，用「快递系统」类比贯穿，短中句。

**借鉴**：**交付物演示**——「打开 Chrome 开发者工具，发一个真实请求」的教法，正是我们 say 字段「拿 X 举例、逐段指出」的英文章节版；前置知识声明（「你需要先懂什么」）对应 related 的先学谁。
**不抄**：整篇围绕一个类比的写法——卡片装不下。

### 7. 参照系：本站（原站卡片词典体）

q 14–22 字问句 + a 41–56 字定义/枚举/边界 + say 51 字指令，单卡 117 字。与 MDN/Codecademy 的词典体同族，但单位长度只有它们的 1/10，且把「深度」外包给 say（现场问 AI）和更多卡片。**这是全行业少见的「词典卡片 + AI 取深度」混合体**——v5 的定位就是沿着它做密度增强。

## 三、对 v5 铺量的操作结论

**v5 被验证的三点**（六家原文佐证）：
1. 定义先行 + 实例枚举 + 边界否定 = 词典体的通用骨架（MDN/Codecademy/原站一致）；
2. 类比与人格化只在教程体成立，词典体（卡片）里是异物——v5 禁类比、禁教练腔是对的；
3. 枚举外置（表格/图/链接/测验）是行业共识——我们的 quiz + 词条粒度就是对应实现。

**铺量时吸收两个新手法**（不改门禁，写 explain/quiz 时直接用）：
1. **拆字枚举**：中文复合术语优先拆字面——「环境变量：环境 + 变量」「状态码：给状态编的码」；拆完再给实例。英文术语则拆词（Cookie 本义小饼干可不拆，Webhook = Web + Hook 拆了就懂）。
2. **辨析题**：quiz 至少一半用「这句说法对不对、错在哪」题型（比三选一场景题更能堵住初学者的高频误解）。

**一条要守住的分界线**：看到好文案先问「它是什么文体」。长文里的优点（类比、玩梗、人格化、铺垫）搬进卡片全部变成 AI 味。v5 的敌人从来不是「写得生动」，是「文体错位」。
