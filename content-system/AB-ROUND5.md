# A/B 对照 · 第 5 轮（v5 标准首验）

> 对照对象：原站快照卡片 vs 本次 v5 重写稿。验收标准：**新版每 1 字信息量 ≥ 原站，且确实多给了东西**。
> 原站原文逐字取自 `main-site-snapshot/index.html` 的 entries 数组。

## HTTP（网络与接口 · 入门）

### 大白话场景 q

| | 文本 | 字数 |
|---|---|---|
| 原站 | 浏览器和服务器按什么规矩说话？ | 15 |
| 新版 | 浏览器向服务器要东西，凭什么总能对上话？ | 20 |

增量：多了「要东西」这个具体动作，悬念（凭什么对上话）有了画面落点；不再是纯抽象提问。

### 一句话讲解 a

| | 文本 | 字数 |
|---|---|---|
| 原站 | HTTP 是网络请求与响应的通用协议，规定方法、地址、头信息和内容怎样组织。HTTPS 则在其外面加上加密保护。 | 56 |
| 新版 | HTTP 规定浏览器和服务器怎么传消息：请求写明方法、地址和头信息，响应带回状态码和内容。加层加密就是 HTTPS。 | 58 |

信息单元核算：

| 单元 | 原站 | 新版 |
|---|---|---|
| 1. 定义（双方传消息的规矩） | ✓ | ✓（动词式定义，双方点名） |
| 2. 方法 | ✓ | ✓ |
| 3. 地址 | ✓ | ✓ |
| 4. 头信息 | ✓ | ✓ |
| 5. 内容组织 | ✓ | ✓（响应带回内容） |
| 6. HTTPS = 加一层加密 | ✓ | ✓ |
| 7. **状态码** | ✗ | **✓ 新增** |
| 8. **请求/响应两侧分工**（请求写什么 vs 响应带什么） | ✗ | **✓ 新增** |

密度：原站 6 单元 / 56 字 = **0.107**；新版 8 单元 / 58 字 = **0.138**。原站全部单元无减损。

### 跟 AI 说 say

| | 文本 | 字数 |
|---|---|---|
| 原站 | 能围绕“HTTP”回答这个问题吗：浏览器和服务器按什么规矩说话？ 我想看一个具体场景，不要一串抽象术语。 | 52 |
| 新版 | 我刚碰到“HTTP”。请拿“提交登录表单”这一次请求举例，逐段指出浏览器写了什么、服务器回了什么，状态码和头信息各在哪里；先别讲协议历史。 | 69 |

增量：交付物从「一个具体场景」升级为「一次真实请求的逐段拆解」（AI 会给出可读的请求/响应原文结构）；新增反向约束「先别讲协议历史」，堵住 AI 惯性的 RFC/版本史输出。

## 状态（交互与体验 · 入门）

### 大白话场景 q

| | 文本 | 字数 |
|---|---|---|
| 原站 | 按钮为什么一会儿能点，一会儿变灰？ | 17 |
| 新版 | 点赞变红、购物车加一，页面靠什么记住这些？ | 21 |

增量：从单一现象换成两个可自查的生活现象（点赞、购物车），「靠什么记住」直指状态的本质问题。
原站的「变灰」现象未丢弃——移入新版 say（见下）。

### 一句话讲解 a

| | 文本 | 字数 |
|---|---|---|
| 原站 | 状态是界面此刻记住的情况：是否登录、输入了什么、数据是否加载。界面根据状态决定显示什么、允许什么操作。 | 51 |
| 新版 | 状态是页面此刻记住的数据：点赞数、输入框文字、是否登录。数据一变界面跟着重画；刷新即清零，长期保存交给后端。 | 54 |

信息单元核算：

| 单元 | 原站 | 新版 |
|---|---|---|
| 1. 定义（页面此刻记住的东西） | ✓「情况」 | ✓「数据」（更准确：状态就是数据） |
| 2. 登录与否 | ✓ | ✓ |
| 3. 输入内容 | ✓ | ✓ |
| 4. 数据加载中 | ✓「数据是否加载」 | ✓「点赞数」（换成更日常的实例） |
| 5. 界面随状态变化 | ✓「决定显示什么」 | ✓「数据一变界面跟着重画」（点出重画机制） |
| 6. 决定允许什么操作 | ✓ | 移入新版 say（「按钮何时该变灰不可点」） |
| 7. **刷新即清零（易失性）** | ✗ | **✓ 新增** |
| 8. **长期保存归后端（去向）** | ✗ | **✓ 新增** |

密度：原站 6 单元 / 51 字 = **0.118**；新版 7 单元 / 54 字 = **0.130**（单元 6 仍由 say 承接，未丢失）。

### 跟 AI 说 say

| | 文本 | 字数 |
|---|---|---|
| 原站 | 我想真正理解“状态”。按钮为什么一会儿能点，一会儿变灰？ 能先给一句话结论，再展开举例吗？ | 45 |
| 新版 | 我想真正理解“状态”。请用“点赞按钮”从点击到变红的全过程举例，说明数据存在哪、界面何时重画、按钮何时该变灰不可点；先别提框架名词。 | 66 |

增量：交付物是「从点击到变红的全过程」三个具体追问（存哪/何时重画/何时禁用）；反向约束「先别提框架名词」防止 AI 一开口就是 React/Vue，对零基础读者是关键保护。原站的「变灰」悬念在此完整保留。
