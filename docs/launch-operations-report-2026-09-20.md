# 网站上线运营研究与90天落地规划

日期：2026-09-20。AI 起草，基于当前工作区只读检查、一次生产构建和公开网络调研。本文是决策与执行方案，不代表已经上线、完成安全审计或验证商业需求。

## 1. 结论与适用前提

建议把现有复刻站转为「面向中文 AI 编程初学者的项目实战学习站」，先用一个完整任务验证价值：**让第一次用 AI 做网站的人，理解必要概念、完成操作并交付一个可展示的页面。**

现有术语图鉴是检索入口，练习是理解检查，课程是行动路径。真正值得继续投入的差异化，是用户最终完成了什么，以及卡住时能否得到帮助。暂不建议同时建设通用知识平台、社区、AI 导师、付费会员和完整学校管理系统。

这项判断的依据是：你已有可复用前后端、校园与线下活动接触机会、教学产品经历，以及明确提过的 FDE 方向。将网站用于真实用户交付，也能积累需求发现、上线维护和效果复盘的案例。

**尚未确认**：当前预算、每周可投入时间、域名和服务器归属、内容商业使用授权、现有用户量、收入优先级，以及之前计划中的活动是否已发生。本文以「单人主导、国内中文用户、每周10小时、先验证后扩大」为工作假设；不是已确认的个人事实。

最强反对意见：你可能只想经营一个轻量、随用随查的工具站；项目教学会增加内容和服务负担。若访谈显示用户主要在工作时快速查词、几乎不需要学习路径，而查词复访和自然推荐稳定，应该保持工具站定位。若学校已明确提出采购需求和预算，则应提前转向组织试点。

## 3. 方法论调研：采用哪些，何时不用

来源分为官方/作者方法、从业案例、社区讨论三类。方法论权威性不等于对本项目有效；热度仅说明关注度，不能作为因果证据。以下针对本站的实施方案均是本报告建议。

| 方法 | 一手依据 | 应用于本站 | 局限与纠偏 |
| --- | --- | --- | --- |
| Build–Measure–Learn | [Eric Ries：Lean Startup](https://theleanstartup.com/principles) | 每周只验证一个假设，写清用户、动作、观察窗口与下一步 | 容易把频繁改功能当作学习；必须保留行为证据 |
| The Mom Test | [Rob Fitzpatrick作者官网](https://www.momtestbook.com/) | 问上次做网站卡在哪里、怎么解决、付出什么，再观察实际操作 | 访谈可能失真；与现场任务、回访和实际承诺交叉验证 |
| Do Things That Don't Scale | [Paul Graham原文](https://paulgraham.com/ds.html) | 手动招募前10—20人，亲自观察并帮助完成任务 | 人工陪跑可能掩盖产品难用；分开统计有辅助和无辅助完成率 |
| PMF调查 | [Superhuman创始人案例](https://review.firstround.com/how-superhuman-built-an-engine-to-find-product-market-fit/) | 有持续使用者后调查“不能再用会怎样”，再分析共同需求 | 40%“非常失望”是经验信号；小样本、熟人和筛样不能证明PMF |
| North Star | [Amplitude框架](https://amplitude.com/books/north-star/about-north-star-framework) | 用真实学习成果组织指标，而非只看访问量 | 答对题或上传链接可能被刷；须抽查实际理解与作品 |
| RICE优先级 | [Intercom原始说明](https://www.intercom.com/blog/rice-simple-prioritization-for-product-managers/) | 有用户证据后按覆盖人数、影响、信心和工时比较需求 | 初期覆盖和影响多为猜测；授权、安全、数据损失风险优先处理 |
| 提取练习 | [Retrieval Practice研究者资源](https://www.retrievalpractice.org/retrievalpractice) | 看完解释后合上答案，独立回答，再做新情境题和延迟复习 | 重复猜同一道判断题不能证明学会，也不能替代真实交付 |
| JavaScript SEO | [Google官方指南](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) | 对原创核心页面提供可抓取正文、独立元数据和正确链接 | Google能处理部分JS不等于所有爬虫均能；SEO不替代需求验证 |

## 4. 定位与路线选择

### 竞争边界

[VibeHub原站](https://vibe-hub.org/en)本身已提供相关术语内容；[roadmap.sh](https://roadmap.sh/)覆盖学习路线；[The Odin Project](https://www.theodinproject.com/paths)提供项目式开发课程。仅复制结构、翻译或增加词条，很难证明独立价值。上述是产品功能参照，不是市场份额或收入比较。

候选定位：**“帮助中文AI编程初学者，从看不懂术语到交付第一个可展示项目。”** 首批用户优先限定为「近一个月尝试过用AI做网页、已经卡住、有一个实际作品要交付的人」，而非所有对AI感兴趣的人。

| 路线 | 支持理由 | 最强反对理由 | 决策信号 |
| --- | --- | --- | --- |
| 免费实战学习站+限额工作坊，优先试验 | 能复用现有功能，也适合线下观察和FDE案例积累 | 用户付费意愿未知，人工服务不易扩张 | 用户交付作品、重复求助并愿意为反馈付费 |
| 教师/社团活动配套，条件性推进 | 可聚合一批真实使用者，组织方可能付费 | 使用者与买单人不同，采购和交付周期较长 | 至少2位明确负责人愿意安排试点并说明验收与预算 |
| 纯工具/内容站，保留备选 | 维护相对轻，适合即用即走 | 广告和订阅收入需要规模，易被替代 | 无辅助查找成功、任务触发复访、自然推荐持续 |

三类利益相关者的约束同时纳入：学习者要少注册负担和可见成果；你要控制维护工时并形成可展示案例；原作者要内容与品牌权利得到尊重；学校或活动主办方要交付稳定、费用明确、数据处理清楚。

### 首期核心路径

入口说明具体结果 → 选择“完成一个活动介绍页” → 按需查10—15个原创概念 → 操作示例 → 独立完成3个检查点 → 提交作品链接或截图 → 获得反馈 → 一周后修改一次作品。

作品验收：能说明页面服务谁、有清晰主操作、手机可用、链接有效、能解释一次修改及原因。第一版可人工评审，暂不开发自动评分器。注册只在跨设备同步确有需求时出现。

首期保留：必要检索、少量高质量示例、一个实战路径、反馈入口。暂缓：全量英文化扩展、论坛、积分、排行榜、复杂支付、AI生成题库、通用CMS、学校后台。现有代码不因此删除，但公开范围要与权利清单一致。

## 5. 公开上线之前的条件

### 内容与品牌：第一道门

现有 `docs/asset-rights-ledger.md` 只覆盖部分素材；还需覆盖课程正文、题干答案、反馈解释、图示、字体、Demo素材、更新日志和社交链接。清单字段：对象、来源、作者、授权范围、凭证、商用/改编/再分发条件、署名要求、上线决定。

未获得明确授权的内容，选择取得许可、独立创作替换，或不公开。**只换Logo、标注来源或免费开放，均不能直接推出整站复制可以公开经营。** 这是风险判断而非对具体作品的侵权裁定；法律依据见[全国人大《著作权法》](https://www.npc.gov.cn/c2/c30834/202011/t20201119_308796.html)。

最低成本路线：先发布一组原创概念、原创案例和一条原创实战路径，不让全部旧内容的处理阻塞访谈；未清权素材既要移除入口，也要从发布产物中排除，不能仅靠隐藏菜单或noindex。

### 技术发布清单

| 优先级 | 工作 | 完成标准 |
| --- | --- | --- |
| P0 | 独立品牌与内容范围 | 自有名称、图标、页脚、联系入口；所有公开内容有可追溯使用依据 |
| P0 | 决定账号是否首发 | 不首发则显式关闭注册登录及自动同步请求；首发则完成下列认证项 |
| P0 | 正确API地址 | 生产请求不含localhost、127.0.0.1或HTTP混合内容；失败有清晰反馈 |
| P0 | HTTPS与认证 | 正确baseURL和trustedOrigins、Secure/HttpOnly Cookie；实测注册登录登出、会话失效 |
| P0 | 账号恢复与滥用治理 | 明确邮箱验证、找回密码方案；核验所用Better Auth版本的限流并测试；补充业务接口限流 |
| P0 | 生产数据与备份 | 独立生产库、独立凭据、最小权限；备份恢复演练通过；不覆盖开发数据 |
| P0 | 用户数据处理 | 说明收集用途、保存期、联系和删除方式；注销/删除至少有可执行人工流程 |
| P0 | 核心流程验收 | 手机/桌面完成阅读、练习、提交、刷新；启用账号时增加跨设备及同步测试 |
| P0 | 回滚与发布边界 | 可还原上一版静态产物；数据库变更另设兼容与恢复步骤；不发布.env和证据目录 |
| P1 | 可观测性 | 健康检查、错误率、核心路径监测、费用提醒、反馈入口 |
| P1 | 性能与搜索 | 实测移动网络；再做必要拆包、图片优化、原创核心页预渲染和元数据 |

认证配置依据：[Better Auth Cookies](https://better-auth.com/docs/concepts/cookies)、[Security](https://better-auth.com/docs/reference/security)。官方当前文档不能直接证明本地安装版本行为，执行前应检查lockfile及对应版本。`server/src/app.js` 生产日志分支未沿用开发分支的显式redact设置，应统一检查；本轮没有证据证明已经泄漏。

SQLite不天然禁止生产使用。小规模、单实例、持久磁盘及可靠备份下可以作为过渡选项；多实例或运维要求提升后再选PostgreSQL。跨provider时要新建兼容迁移基线、评估是否需要数据导入、核对约束并演练恢复，不对生产库运行reset。

涉及个人数据时遵循最小必要，分析事件不要记录邮箱、密码、用户输入的完整提示词或项目秘密。[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

## 6. 部署方案：按用户位置和账号需求决定

| 方案 | 适用条件 | 代价与验证点 |
| --- | --- | --- |
| 国内服务器，同域名静态站+/api反向代理 | 核心用户在国内、需要账号，且可以安排备案与运维 | 需明确主体、域名、接入商及备案流程，负责补丁、备份、告警 |
| 静态托管，首发无账号 | 先验证原创学习路径，跨设备同步并非核心 | 发布前需实现关闭账号的明确配置；仍需在目标用户网络实测 |
| 境外静态托管+独立后端 | 目标网络测试通过，愿意承担跨服务配置与数据处理工作 | CORS、Cookie、连接延迟、邮件及数据地区均需检查 |

默认倾向：如果主要面向国内校园且已有可用国内资源，采用一个域名下的静态前端和 `/api` 代理；没有现成资源则先准备可部署产物和原型试用，不急于购买复杂基础设施。

Cloudflare官方给出了Vite构建部署方案，静态发布目录是`dist`；这不代表能原样托管当前常驻Fastify+Prisma服务。[Vite部署指南](https://developers.cloudflare.com/pages/framework-guides/deploy-a-vite3-project/)。Pages有默认SPA回退行为，但无效URL的404语义仍须单独验证。[Serving Pages](https://developers.cloudflare.com/pages/configuration/serving-pages/)。

Vercel Hobby官方限制为个人非商业用途，不能把它作为商业运营免费的默认前提。[Hobby计划](https://vercel.com/docs/plans/hobby)。本报告不提供未经核实的服务器报价，也不保证境外平台在国内的可达性。

国内接入与非经营性备案参考[工信部备案管理办法](https://www.miit.gov.cn/gyhxxhb/jgsj/cyzcyfgs/bmgz/xxtxl/art/2024/art_84a0cfa0ebd049bbbe751dca9a008e56.html)。收费业务是否涉及其他许可，应按具体业务、主体及接入安排核实，不能简单归纳为“有收入就一定需要ICP许可证”。备案等待不计入纯开发工时。

部署时顺序：明确账号和地域 → 确认内容可发布 → 冻结版本并构建 → 预发布环境验收 → 数据备份和回滚演练 → 用户确认后公开发布 → 24小时及7天复查。网站尚未实际部署，本报告没有操作外部账号。

## 7. 首批用户与运营实验

先联系你能直接触达的同学、社团成员、活动组织者；这些是潜在渠道，不是已确认用户。避免同时运营三个平台。前4周以一个线下/社群渠道为主，一个内容平台为辅。

每条内容只解决一个实际卡点，例如“AI改完网页为什么刷新后打不开”“第一次部署前要检查哪五件事”。内容链接指向对应任务页，而不是笼统导向站点首页。每周一份原创案例，改成适合主平台的形式，不要求日更。

| 实验 | 样本与动作 | 成功信号（本报告自定） | 不满足时 |
| --- | --- | --- | --- |
| 问题访谈 | 10位近一个月实际做过网页的人；至少一半非亲密熟人 | 至少5人有同类最近障碍、能说明当前解决成本 | 改用户分群或任务，不急着增加功能 |
| 首次价值 | 5人无辅助完成核心任务，记录卡点；随后可提供帮助 | 至少3人无辅助完成，并能解释关键概念 | 优先改路径、文案和示例 |
| 小批内测 | 20位合格用户分两批，每批有完整7天观察窗口 | 至少10人完成首次任务，至少6人发生有意义复访 | 区分网络、难度、缺乏任务需求三个原因 |
| 价格验证 | 对完成过任务的人提出一场内容、时间、价格明确的小班 | 5笔真实报名付款或2个组织明确付费试点 | 不用点赞替代订单；访谈拒付原因，重新定义服务 |

上述是投入决策门槛，不是统计显著性标准或行业基准；报告分子/分母，不只报告百分比。付款实验在服务内容、交付能力、退款规则和合规收款方式明确后开展，本轮不执行收款或发消息。

访谈提纲：上次要做什么？具体卡在哪里？当时怎样解决？花了多久或多少钱？能否展示当时材料（去除敏感信息）？愿不愿意在一个明确时间尝试这条路径？避免只问“你喜欢吗”“以后愿意付费吗”。

## 8. 指标与每周复盘

候选北极星指标：**每周完成一项合格项目任务的独立学习者数**。作品按固定量规人工抽查；按用户去重，有辅助/无辅助分开。早期不要把答题次数当作学习成果。

| 指标 | 口径 | 用途 |
| --- | --- | --- |
| 首次完成率 | 完成首项任务的新用户/开始该任务的新用户 | 发现路径阻力 |
| 首次价值时间 | 从任务开始到首次合格提交的时长中位数 | 判断学习成本是否下降 |
| 7日有意义复访 | 首次激活后第1—7天完成新任务或实质修改作品人数/已满7天观察窗口的激活人数 | 不把未满窗口的用户计入分母 |
| 学习迁移 | 延迟后能独立完成新情境任务的人数/接受复测人数 | 避免熟记答案造成虚假提升 |
| 渠道有效获客成本 | 该渠道现金支出及工时分别记录/该渠道首次合格完成人数 | 不以点击成本决定渠道 |
| 服务负担 | 每位活跃用户的支持分钟数、每单交付小时数 | 防止人工服务不可持续 |
| 商业结果 | 真实实收、退款、直接成本、负责人时间 | 区分收入、现金贡献与经济利润 |

事件最小集合：`task_start`、`term_view`、`practice_answer`、`task_submit`、`task_pass`、`feedback_submit`。字段仅保留匿名或去标识标识、任务ID、渠道、时间、版本、是否辅助；事件去重、过滤开发测试流量。前20人可以在告知后用简易表格和人工观察，不必先搭数据平台。

每周复盘30分钟：本周假设 → 实际样本与行为 → 三个主要卡点 → 保留/修改/停止的决定 → 下周一个实验。小流量时优先可用性观察，避免没有统计功效的A/B测试。

## 9. 收入探索与投入上限

优先试验一次性、交付范围明确的项目工作坊或项目反馈服务；基础知识保持可访问。暂不以订阅为默认，因为持续付费需要持续新增价值与稳定留存。

以下为试验设定，不是市场价格、销售预测或已批准预算：可先测试99元/人的小班、10个席位。满额实收990元；若直接成本150元，准备和交付共8小时，现金贡献为840元，折合105元/小时，尚未扣税费及其他费用。若仅3人付费且同样投入8小时，则贡献147元、约18元/小时。由此倒推最低开班人数和取消退款规则，而非先建设支付系统。

| 资源假设 | 建议范围 |
| --- | --- |
| 每周5小时以内 | 轻量原创工具站+访谈；双周一个实验，90天计划顺延 |
| 每周约10小时 | 4小时产品内容、3小时用户观察、2小时分发、1小时维护复盘 |
| 每周15小时以上且有人协作 | 在核心路径稳定后增加一次组织试点，仍不同时开多条产品线 |

建议首月现金预算上限先设为300元（待你确认），按域名摊销、计算/存储、备份、邮件分别记账；超出时缩减范围并重新决策。此数是支出约束，不承诺覆盖任意平台或带宽。先不付费投放、不批量采购内容工具；任何付费采购由你确认。

## 11. 什么证据会改变建议

- 已有明确授权及用户数据：可以跳过重复发现，但需核对授权范围和样本口径。
- 多数用户只想快速查概念、没有项目学习需求：转轻量工具站，用查找成功与任务触发复访衡量。
- 教师/组织明确预算、负责人及验收任务：优先组织试点，但不因一次口头兴趣建设管理平台。
- 连续两轮合格样本仍无法完成任务或回访：停止扩内容、收费开发和投放，重新选择问题。
- 连续4周稳定产生成果、存在真实付费且支持工时下降：再考虑会员、自动化和扩渠道。
