# VibeHub 桌面端复刻执行计划

更新：2026-09-20  
目标站：`https://vibe-hub.org/`  
范围：仅桌面端，基准视口为 Chromium `1440×900`、DPR 1；移动端暂不作为交付或验收范围。

## 0. 交付边界

本轮交付的是本地可运行、可编辑的 React 等价实现（T2-AI），以原站在指定桌面状态下的可观察行为作为对照；不是原站的人类原始源码，也不包含原站无法从浏览器获得的服务端、账号、数据和权限系统。

当前仓库默认入口已是独立品牌“起站”，历史 VibeHub 实现不再由 Vite 入口加载。为避免覆盖现有可发布产品，本轮复刻工作先在现有 VibeHub 历史实现和 `replication-evidence/` 中完成证据与验收；只有在桌面验收达标后，才单独决定是否切换默认入口或导出为独立项目。

## 1. 成功标准

### 桌面视觉

- 原站与本地统一浏览器、视口、DPR、字体加载条件和数据状态。
- 每个已纳入范围的页面状态均保存原站基线、本地截图和差异图。
- 关键状态的视觉差异以 `mismatchRatio ≤ 1%` 为机器门槛；字体抗锯齿等环境差异必须单独记录，不能用扩大阈值掩盖布局或素材差异。

### 交互与运行时

- 无 `pageerror`、console error 或本地资源请求失败。
- 交互以原站实际观察为准：触发动作、状态改变、DOM/文档流变化、持久化副作用和禁用状态均须一致。
- 首页、术语详情、练习、课程、Skill 和 Changelog 的关键入口可刷新、可深链访问。

### 工程

- 复刻页面保持 React/HTML/CSS 可编辑，不使用 iframe、整页截图或指向原站的运行时兜底。
- 所有复制或下载的资源必须记入权利/来源清单；没有明确可用权的内容只用于本地对照，不作为独立发布资产。
- 不修改现有“起站”默认入口、后端或部署配置，除非后续明确把复刻版作为发布产物。

## 2. 实施顺序

| 阶段 | 工作 | 产物与验收 | 完成定义 |
| --- | --- | --- | --- |
| P0：基线复核 | 重新采集原站 `1440×900` 的路由、标题、字体、网络资源和关键状态；检查现有证据是否仍有效。 | 更新后的页面/状态清单与截图基线。 | 每项观察均有可复跑操作路径。 |
| P1：风险样本 | 先完整对齐 `/en/html`：首次页、滚动后、Survey 关闭、Quick Check 正确答题。 | 状态机、DOM/样式证据、视觉差异报告。 | 四个状态交互通过，桌面视觉达标。 |
| P2：共享外壳 | 收敛 Header、导航、搜索、主题色、Footer、问卷弹层、字体和路由壳层。 | 共享组件测试和全页截图。 | 所有后续页面共用同一壳层，避免逐页复制 CSS。 |
| P3：内容主路径 | 按“目录 → 详情 → 练习 → 课程 → Skill/Changelog”顺序修复桌面视觉与行为。 | 每类至少一个代表页先达标，再批量扩展。 | 页面清单中每项都有状态、测试和已知差异。 |
| P4：复杂交互 | 单独处理 API 六步流程、Quick Check、收藏、搜索/筛选、Survey 和记忆状态。 | 原站/本地状态转移记录与 E2E。 | 连续操作、刷新及异常输入行为一致。 |
| P5：全站回归 | 路由、可访问性基础、视觉、构建和运行时诊断。 | 最终验证报告、差异清单和可运行命令。 | 未达标项明确保留，不标记为完成。 |
| P6：移动端（后置） | 另建 `390×844` 基线和组件响应式契约。 | 独立移动端验收报告。 | 不与桌面验收混用。 |

| `/en/html` | initial、hero-scroll、survey-skip、quick-answer | 问卷覆盖层、答题反馈导致的文档流变化 |

## 4. 工作规则

1. 每次只处理一个页面族或一个状态机；先通过代表样本，才扩展同类页面。
2. 先从 DOM、computed styles、请求和真实事件获取证据；截图只做验收依据。
3. 修复优先级为：错误/失效资源 → 文档流与布局 → 字体和间距 → 图标/素材 → 动画细节。
4. 原站动态内容、第三方统计和不稳定网络请求要在证据中隔离记录；不能以此修改本地产品行为。
5. 每批完成后仅运行受影响的最小测试集，再在 P5 运行全量回归。

## 5. 当前已知风险与处理

| 风险 | 当前证据 | 处理方式 |
| --- | --- | --- |
| 当前默认入口不是 VibeHub 复刻 | `README.md` 标注 `src/launchApp.jsx` 为当前入口 | 隔离复刻工作，最终再决定集成方式。 |
| 旧视觉报告未达到阈值 | `/en/html` 桌面约 3.6%–3.9% 差异 | 以 P1 新鲜基线重新测量并分区定位。 |
| 现有工作区有未提交改动 | `git status` 显示多处文件改动 | 不回退、不覆盖；每项改动先检查所属实现。 |
| 移动端差异大 | 历史 T2 报告中 390px 维度不匹配 | 按本轮范围明确后置，不计入桌面阻塞项。 |
| 原站内容/素材权利未知 | 浏览器可访问不等于获得再发布权 | 建立资源来源记录，公开发布前替换或取得授权。 |

## 6. 首个落地切片

从 P1 的 `/en/html` 开始，按以下最小闭环执行：

1. 重新采集四个桌面状态及触发步骤。
2. 对照当前历史复刻实现，按屏幕区域定位像素差异。
3. 只修改与该页面共享壳层或 HTML 详情模板直接相关的代码。
4. 重跑四状态视觉比对、对应交互 E2E、构建。
5. 将数值、截图路径和未解决差异回写进差异清单。

只有这个闭环达标，才进入 P2/P3 的批量页面工作。
